# prompts

ループを動かす Claude Code ルーチンのプロンプト。

**これは記録であり、実行されるファイルではない。** ルーチンの実体は claude.ai 側にあり、
ここを編集しても自動では反映されない。変更したら API 経由でルーチンを更新すること。

置いている理由は、リポジトリを見ればループの定義が分かるようにするため。
差分がレビューでき、変更履歴も残る。

| ファイル | 実行 | 役割 | ルーチン ID |
|---|---|---|---|
| [`request-generator.md`](request-generator.md) | 毎朝 04:30 JST | デモ用の依頼を Slack に投稿する | — |
| [`morning-loop.md`](morning-loop.md) | 毎朝 05:00 JST | 修復 → 依頼の取り込み → 実装 PR | `trig_01Jk8hRRB6UfjgjJ44vHnNio` |
| （記録なし） | 毎朝 06:00 JST | レビューして問題なければマージ | — |

レビューは別のルーチンで動かしている。**作る側と見る側を分けるのが目的**なので、
朝のループに統合しない。同じセッションだと実装の文脈を持ったまま自分の差分を
見ることになり、カオス注入を見抜けるかという実験が成立しなくなる。

ルーチン ID は更新のたびに使う。`RemoteTrigger` の `list` はページングが効かず、
使い捨ての `send_later` が一覧を埋めるため、ID を控えておかないと本体に辿り着けない。

## 必要なコネクタ

claude.ai のコネクタとして接続し、ルーチンに添付する。

- **Slack** — 依頼の読み取り、スレッド返信
- **GitHub** — Issue / PR の作成
- **Sentry** — 本番エラーの取得（`morning-loop` のみ）

**ルーチン作成時のコネクタ構成が固定される。** 後からコネクタを追加しても既存の
ルーチンには反映されないため、作り直しが必要。
